## v1.0 之前 · WHEN 层从零到可用

建库前的开发。核心决定与实测结论：

- **三条通路**定型：`INSTANT`（口头提问，跳过视觉门）/ `STANDING`（用户注册的持续监测）/ `ALERT`（系统预置预警，本质是系统给定的 standing query）。
- **视觉门用 SigLIP zero-shot**，不训练任何参数。触发要同时满足两个条件：`lift`（分数相对该 query 自身基线抬升了多少）和 `min_raw`（绝对分数够不够，即东西真的在画面里）。只看前者会被「物体一直在画面里」骗到。
- **慢基线加 bias correction**，收敛从 16.5 秒变成即时（第 8 帧偏差缩小 6 倍）。
- **负样本三态** `off / manual / auto`。实测「通用负样本句子」这条路最差（1/3 命中），比不用负样本还糟。
- **阈值逐条 query 标定**，锚定在 softmax 随机水平。全局一个阈值会让后注册的 query 永远够不到。
- **语音链路**：RMS VAD（环境底噪自标定）+ Whisper 转写与翻译（说中文出英文 query）+ 动作短语改写成画面描述。
- 修掉一个极难定位的 bug：**sounddevice 回调里必须 copy 输入缓冲**，否则录到的全是静音而电平表正常——这才是 Whisper 反复幻觉出 `Thank you for watching!` 的真正原因。

## 2026-09-14 17:09:03 · 修 auto 负样本的三处问题　`242d4a5`

把整个词表对着眼镜实时画面打出完整排名，定位到三个独立问题：

**词表覆盖不足。** 112 条里带 bottle 的只有 `a bottle of oil or sauce`，所以占据眼镜画面中央的水瓶**从来就不是候选项**。把水瓶描述加进去测，它拿到 0.0872、排名 1/113，远超当时第一名的 0.0673——**是覆盖问题，不是检测问题**。词表扩到 174 条。

**选择没有多样性约束。** 一次选出的 6 条里 5 条是画质类，只覆盖 2 个类别。加类别限额（每类最多 2 条）后，三个测试场景的覆盖都升到 4 类，水瓶也进入了眼镜画面的负样本第 4 位。MMR 也实现了但**实测无效**（3 个场景只改变过一次顺序、没改变过集合），默认关闭。

**chance 锚点是道翻不过的墙。** `min_raw ≥ 1.2/(1+K) = 0.171` 是固定值，但分数量纲随负样本贴合度差一个数量级——厨房 auto 下所有 query 的全程峰值只有 0.017–0.094，于是一次都不触发。现在给它加了天花板 `min(chance × 1.2, 统计量 × headroom)`，厨房 auto 恢复触发。

`manual` 模式在两段视频上完全不变。

## 2026-09-14 17:22:41 · 模型加载改为缓存优先　`0ed0698`

启动卡在「加载 SigLIP ...」不动。`from_pretrained` 即使模型已缓存，每次仍会发
HEAD 请求查更新；网络被丢包时它挂在 `socket.connect` 上无限等待，而本地其实什么都不缺。

`mlx_whisper` 同理——每次转写都调 `snapshot_download`，没有本地短路。

两处都改成**先查本地缓存、没有才联网**：SigLIP 加载 1.26 秒且完全不碰网络，
Whisper 仓库解析 1–103 毫秒。缓存里没有的模型照常下载，只是会打印一行提示。

## 跨量纲阈值归一化（优先级最高的未解项）

**问题**：同一套阈值公式要同时管住三种量纲差一个数量级的场景——

| 场景 | query 分数范围 | 原因 |
|---|---|---|
| 眼镜 + auto | 0.01 – 0.09 | 负样本极贴合，query 抢不到 softmax 概率 |
| 书桌 + auto | 0.02 – 0.61 | |
| live 摄像头 | 0.02 – 0.31 | |

现在靠 `μ+kσ`、`chance × multiplier`、`headroom 天花板` 三个约束拼出来，能用但脆，`auto` 在两段视频上仍略逊于 `manual`（厨房 auto 的触发时机偏晚约 12 秒）。

**方向**：把分数本身变成尺度无关的量再定阈值，而不是继续给绝对值打补丁。候选做法是用该 query 分数在自身历史分布中的分位数，或跨 query 的相对排名。

**动手的判据**：当 `auto` 需要在多个环境间通用、且不能接受逐环境调参时。现在默认用 `manual`，这个问题可以放着。
